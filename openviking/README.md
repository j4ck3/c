# OpenViking

Self-evolving context database for AI agents (memory, knowledge RAG, skills) from
[volcengine/OpenViking](https://github.com/volcengine/OpenViking), deployed from the
official image `ghcr.io/volcengine/openviking:latest` (v0.4.17.1 at install).

- **LAN endpoint:** `http://<host>:1933` — Web Studio at `/studio`
- **Docker network:** attached to `npm_services`, so other containers reach it at
  `http://openviking:1933`
- **Auth:** `api_key` mode (not dev mode). Traefik labels for a public host are
  prepared but commented out in `compose.yml`.

## Layout

| File | Purpose |
|---|---|
| `compose.yml` | The stack (single service, official image) |
| `.env` | `OPENVIKING_SERVER_PORT` + `OPENROUTER_API_KEY` (only secret on disk, chmod 600) |
| `/mnt/user/appdata/openviking/ov.conf` | Server config; API key referenced as `${OPENROUTER_API_KEY}` and expanded at runtime from the container env |
| `/mnt/user/appdata/openviking/ovcli.conf` | Default `ov` CLI config inside the container |
| `/mnt/user/appdata/openviking/data` | All context data (agfs + local vectordb) |

The `${OPENROUTER_API_KEY}` in `ov.conf` is expanded by the server on read
(`bootstrap.py` runs `os.path.expandvars`), so the key itself never lands in
`ov.conf` — it lives only in this folder's `.env`.

## LLM provider

OpenRouter (`https://openrouter.ai/api/v1`) via OpenViking's generic
OpenAI-compatible provider, for both models:

- **Embedding:** `openai/text-embedding-3-large`, dimension 3072
- **VLM:** `openai/gpt-4o`

To swap models/providers, edit `ov.conf` (`embedding.dense` / `vlm` sections),
then `docker compose up -d --force-recreate`. OpenRouter model names carry the
vendor prefix (`openai/...`, `google/...`, `qwen/...`). Any OpenAI-compatible
endpoint works the same way (custom `api_base` + `provider: "openai"`).

## Accounts / keys

- **Root key** — in `ov.conf` (`server.root_api_key`). For admin operations only:
  `docker exec -it openviking ov --sudo admin list-accounts`. Root keys cannot
  touch tenant data in `api_key` mode.
- **Admin user key** — in `ovcli.conf`. Account `home`, user `jacob` (created via
  `POST /api/v1/admin/accounts`). This is the key your agent integrations should
  use (`OPENVIKING_API_KEY` / `X-API-Key`).
- Read the keys from the two config files; they are not printed anywhere else.

## Operating

```bash
cd /mnt/user/documents/compose/openviking
docker compose up -d            # start
docker compose logs -f openviking
docker exec -it openviking ov status

# quick CLI tour (inside container)
docker exec -it openviking ov ls viking://resources/
docker exec -it openviking ov add-resource <url>
docker exec -it openviking ov find "query"
```

Changing the OpenRouter key: edit `.env`, then
`docker compose up -d --force-recreate`.

  1.5 GB with `node_modules`/`.convex`/`.git` and real `.env` secrets — the
  stage excludes all of those (rsync filters in this README's git history).
  Re-stage + re-run `ov add-resource /app/.openviking/imports/projectx
  --parent-auto-create viking://resources/projectx` after significant changes
  to refresh.
